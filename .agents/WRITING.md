# Long-form and durable writing

Read this guidance when writing or editing reports, guidance, documentation, comments, summaries, or task trackers.

## Structure long-form prose

- Organise the content around the reader's task. Give each section and paragraph one topic.
- Use exact names, numbers, and dates. Define unavoidable jargon on first use.
- Use sentence case headings and descriptive link text. Use numbered lists only for steps that run in order.
- Create emphasis through order and structure. Reserve bold text for literal interface labels.

## Maintain durable documentation

- Read the code, schema, configuration, or output that defines the behaviour before documenting it.
- Write durable docs as the present contract: current behaviour and constraints. Keep comments focused on those points or actionable follow-up.
- Record reader-relevant history in a changelog. Version control keeps other history.
- Regenerate derived examples from their authoritative source instead of paraphrasing them.
- Keep task trackers limited to unfinished, actionable work. Delete completed or stale items.
- Keep one authoritative document for each subject. Consolidate surviving guidance and delete superseded notes or temporary specifications.
- Finish when every affected durable surface agrees with its authoritative source and no stale contradiction remains.
